**Fleet** is a self-hosted control plane for coding agents that run on machines
you own. It gives you one browser UI for starting agent sessions, browsing code,
reviewing Git changes, and approving tool permissions — while the agents,
repositories, and credentials stay on your hardware.

Fleet is built for developers who want the convenience of a hosted coding agent
without handing their filesystem or shell to a third party. A small daemon runs
on each machine, owns the local workspace and agent processes, and connects out
to the admin. The admin routes requests; it never reads your files directly.

## How it fits together

<pre class="mermaid">{`
flowchart LR
  B["Browser SPA"] -->|"HTTPS + bearer token"| A["fleet-admin"]
  C["fleet CLI"] -->|"HTTPS + bearer token"| A
  A -->|"reverse WSS /ws/machine"| D["fleet-daemon"]
  D --> W["Workspaces"]
  D --> P["Agent providers"]
  D --> G["Git repositories"]
  D --> F["Local filesystem"]
`}</pre>

| Component | Responsibility |
| --- | --- |
| `fleet-admin` | Serves the web UI and REST API, authenticates users, authorizes requests, keeps durable metadata, and routes RPCs to connected machines. |
| `fleet-daemon` | Runs on the machine that owns the code. It registers workspaces, reads files, runs Git, spawns agents, and streams events back to the admin. |
| Web UI | Machine dashboard, workspace explorer, Monaco viewer and diff, Git panel, and streaming agent sessions. |
| `fleet` CLI | Onboarding, service lifecycle, the admin REST API, local daemon helpers, and guided remote access. |

A daemon opens a single outbound WebSocket to the admin and keeps it open.
Authentication uses a short-lived pairing code for the first connection and a
per-machine token plus an Ed25519 challenge-response for every later one. The
admin sends requests down the same socket and receives events, heartbeats, and
durable event cursors back up it.

## What you can do

| Capability | What you get |
| --- | --- |
| Agent sessions | Create multiple sessions per workspace, stream messages and tool calls, approve or reject permissions, interrupt, resume, and close or delete sessions. |
| Session recovery | The daemon owns the transcript. After a restart, active sessions are restored as read-only `interrupted` records with their turns, messages, and tool calls intact. |
| Providers | `mock` for deterministic tests, Claude Code CLI, Codex app-server, OpenCode serve, and a generic PTY adapter. Unavailable providers report why. |
| Workspaces | Register repositories or directories, browse a lazy directory tree, search, read files with ETag caching, and react to file changes. |
| Git | Status, branches, log, summaries, unified diffs, untracked files, stage and unstage, commit, and checkout. Writes sit behind an independent token and audit log. |
| Access control | Bearer tokens, `admin` / `member` / `viewer` roles, organization-scoped resources, machine key pinning, key rotation, and permanent machine revocation. |
| Remote access | Run the admin behind Cloudflare Tunnel and Access, or keep it private on a Tailscale tailnet. |

## Current scope

The supported release is the **single-machine version**: one `fleet-admin`
manages one `fleet-daemon`, and that daemon can host multiple workspaces and
sessions. Multi-machine fleets, multi-instance admins, and multi-tenant
operations are groundwork and roadmap items, not part of the current support
commitment.

See [Status and roadmap](/project/status/) for the full breakdown.
