The admin exposes a versioned JSON API at `/api/v1` on its HTTP listener. The web UI and the `fleet` CLI both use it. Every endpoint except health is authenticated.

## Authentication

Send a bearer credential on every protected request:

```http
Authorization: Bearer flu_...
```

Three credential kinds are accepted:

| Credential | Issuer | Scope |
| --- | --- | --- |
| `fla_...` | Admin setup | Legacy bootstrap token. Sees and manages every organization; intended for initial setup and CLI recovery. |
| `flu_...` | `POST /api/v1/users` or a token rotation | A global user account. Its role and resources come from memberships, so the same account can hold a different role per organization. |
| Browser session cookie | `POST /api/v1/auth/session` | A user account, after its bearer token was exchanged for an HttpOnly cookie. Unsafe methods also require the CSRF token. |
| `flm_...` | Machine pairing | A per-machine credential used by the daemon WebSocket at `/ws/machine`, not by the REST API. |

Roles are `owner`, `admin`, `member` and `viewer`. Viewers may only use safe methods (`GET`, `HEAD`, `OPTIONS`), with one exception: they may rotate their own token. Admin-only routes perform additional role checks. User-scoped callers see only resources owned by an organization they belong to.

## OAuth sign-in

`GET /api/v1/auth/providers` lists the configured providers and whether the deployment still needs its first account:

```json
{ "providers": ["github", "google"], "bootstrap_required": false, "bootstrap_email_configured": true }
```

`GET /api/v1/auth/login/{provider}` creates a single-use state and PKCE verifier, stores them for ten minutes, and redirects to the provider. The provider returns to:

```text
GET /api/v1/auth/callback/{provider}?code=...&state=...
```

The state is consumed exactly once. The server exchanges the code, requires a verified email, resolves the account by linked identity and then by email, and creates a personal organization for a new account. Before the deployment has any user, the email must appear in `auth.bootstrap_admin_emails`; afterwards new accounts are self-service with a personal organization only. Pending invitations for the verified email are accepted on every sign-in.

Success redirects to `/` with the session cookies set. Failures redirect to `/?auth_error=<code>` so the login page can explain them without exposing provider responses or storage details.

## Browser sessions

`POST /api/v1/auth/session` exchanges a user bearer token for a session:

```http
POST /api/v1/auth/session
Authorization: Bearer flu_...
```

The response sets an HttpOnly session cookie and a readable CSRF cookie, and returns the caller's `Me` object. The legacy admin token is rejected with `403`: it cannot own a browser session. A session is valid for `auth.session_ttl_days` and is revoked after `auth.session_idle_ttl_days` without activity.

Every unsafe method authenticated by the cookie must echo the CSRF value:

```http
X-CSRF-Token: <value of the fleet_csrf cookie>
```

Bearer-authenticated requests are exempt because a cross-site page cannot set an authorization header. Session creation, logout and the event-ticket endpoint also reject a foreign `Origin`.

`POST /api/v1/auth/logout` revokes the presented session, clears both cookies, and returns `204`. It accepts an expired session so the browser can always clear stale cookies; the CSRF header is required whenever a session cookie is present.

`GET /api/v1/health` is public and returns the server version plus the number of live machine connections:

```json
{ "ok": true, "version": "0.1.0", "machines_online": 2 }
```

## Errors

Failures use the stable envelope:

```json
{ "code": "machine_offline", "message": "machine m_123 is offline" }
```

`details` is optional. The `code` is stable API; do not parse `message`. See [Errors](/reference/errors/) for the full mapping and remedies.

## Response conventions

- JSON is the default representation. File reads return JSON content with an `ETag`; conditional reads can return `304 Not Modified`.
- Some delete routes return `204 No Content`; session and command routes return a JSON result, often `{ "ok": true }`.
- Cross-organization access returns `404 Not Found` rather than `403 Forbidden`, so the API does not confirm that another organization's resource exists.
- A machine that is not connected returns `503 Service Unavailable` with code `machine_offline`.
- State conflicts return `409 Conflict`, for example removing a workspace that still has active sessions.
- Request bodies are parsed strictly: malformed JSON or a missing required field returns `400` with code `invalid_request`.

## Organization scoping

A request selects its active organization with:

```http
X-Fleet-Org: org_...
```

Without the header the server picks a team organization the caller belongs to, falling back to the personal space. Membership is validated on every request; naming an organization the caller does not belong to returns `403`, and object routes reject resources owned by another organization with `404`. The legacy admin token is unscoped and ignores the header for authorization.

## Event WebSocket

Browsers cannot attach an authorization header to a WebSocket upgrade, so the browser mints a single-use ticket:

```http
POST /api/v1/realtime/ticket?org_id=org_...
```

The response is `{ "ticket": "...", "org_id": "org_...", "expires_in": 60 }`. Connect with the ticket; it is bound to the caller and organization, expires after 60 seconds and is consumed on first use:

```text
GET /api/v1/events?ticket=...
```

Non-browser clients may still authenticate the upgrade with `Authorization: Bearer flu_...`. The `?token=` query form is rejected because URLs leak into logs and history. The socket re-authenticates every 15 seconds so deleted users, revoked sessions and rotated tokens stop receiving events. It sends pings every 25 seconds and emits a `platform.lagged` event if the subscriber falls behind; refetch current state when you see one.

## Git write token

Git write routes are authorized by the normal bearer token. When `git.write_token` is set, they additionally require:

```http
x-fleet-git-token: <write token>
```

A missing or wrong write token returns `403` without invalidating the user's session. Set `git.allow_writes = false` to disable writes entirely.

## Pagination and limits

| Endpoint | Parameter | Default | Range |
| --- | --- | --- | --- |
| `GET /api/v1/audit` | `limit` | `100` | `1`-`500` |
| `GET /api/v1/workspaces/{id}/tree` | `limit`, `cursor` | `200` | `1`-`1000` |
| `GET /api/v1/workspaces/{id}/search` | `max_results` | `200` | `1`-`1000` |
| `GET /api/v1/workspaces/{id}/git/log` | `limit` | `50` | `1`-`500` |

Directory listings are cursor-paginated: pass the returned cursor to fetch the next page. Search and Git log cap results at the requested maximum. Audit returns newest entries first.
