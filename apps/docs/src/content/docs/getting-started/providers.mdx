A provider is the daemon-side adapter that starts and controls one kind of
coding agent. Every provider implements the same session interface, but they
differ in transport, tool reporting, and whether Fleet can route permission
approvals. The daemon reports each provider's capabilities to the admin, and
sessions can only use a provider the machine reports as available.

## How availability works

The daemon registers six adapters: `mock`, `claude`, `claude-acp`, `codex`,
`opencode`, and, when configured, `generic`. A provider reports
`available: false` when its executable is missing. A missing binary does not stop the daemon; it only
removes that provider from the usable set in the UI.

List what the local daemon detects:

```bash
fleet daemon providers
```

The command prints the provider descriptors as JSON, including `available` and
`capabilities`. For a remote machine, use
`fleet admin machines providers <machine-id>`. The Machines page shows the same
information in the UI.

## Capability matrix

| Provider | Transport | Streaming | Tool calls | Approvals | Questions | Resume |
| --- | --- | --- | --- | --- | --- | --- |
| `mock` | In-process | Yes | Yes | Yes | Yes | Yes |
| `claude` | CLI stream-json | Yes | Yes | No | No | Yes, when `--resume` is supported |
| `claude-acp` | ACP v1 over stdio | Yes | Yes | Yes | Yes | No |
| `codex` | app-server JSON-RPC over stdio | Yes | Yes | Yes | Yes | Yes |
| `opencode` | HTTP + SSE | Yes | Yes | Yes | Yes | Yes |
| `generic` | PTY | Yes | No | No | No | No |

All providers support interrupt. `mock`, `claude`, `claude-acp`, `codex`, and
`opencode` emit structured events; `generic` emits terminal text only.

## Mock provider

`mock` runs in-process and needs no binary, credentials, or network access. It
is always available and deterministic, which makes it the default choice for UI
development, smoke tests, and the [first session](/getting-started/first-session/)
walkthrough.

Message content selects a scenario:

| Content contains | Behaviour |
| --- | --- |
| `/tool` | Requests permission for a `Bash` tool call |
| `/question` | Asks two questions and waits for an answer batch |
| `/fail` | Fails the turn with `mock_failure` |
| `/slow` | Streams 50 words with 100 ms delays |
| `/never` | Runs until interrupted or shut down |
| Anything else | Streams `Echo: <text>` word by word |

## Claude Code

The `claude` adapter launches the Claude Code CLI in print mode:

```text
claude -p --input-format stream-json --output-format stream-json --include-partial-messages --verbose
```

The binary must be installed for the daemon account and resolvable on its
`PATH`. The adapter adds `--resume <session-id>` when resuming a session and
reports resume as available when the binary supports it.

Fleet reports `permission_approval: false` and `user_questions: false` for
Claude. Print mode has no documented permission-response channel in this
adapter, so approve or deny tool use through Claude Code's own configuration
rather than the Fleet approval dialog.

## Claude Code via ACP

The `claude-acp` adapter launches
[`@agentclientprotocol/claude-agent-acp`](https://www.npmjs.com/package/@agentclientprotocol/claude-agent-acp)
and speaks Agent Client Protocol v1 over stdio:

```text
claude-agent-acp
```

Install it for the daemon account or point `agent.claude_acp_bin` at the
executable. This adapter supports structured streaming, tool calls, permission
approvals, and user questions. The daemon registers it only when the binary is
available; the legacy `claude` adapter remains available for stream-json mode.

## Codex

The `codex` adapter starts the Codex app server and speaks JSON-RPC 2.0 over
newline-delimited JSON on stdio:

```text
codex app-server --listen stdio://
```

Install the `codex` CLI for the daemon account. Codex supports structured
streaming, tool calls, permission approvals, and resume, so its sessions use the
same approval dialog and lifecycle controls as the mock provider.

## OpenCode

The `opencode` adapter talks to the OpenCode v2 HTTP API and consumes the
server-sent-events endpoint for streaming. By default the daemon starts a private
`opencode serve` process on a random loopback port and reuses it for its
sessions.

Set `OPENCODE_SERVER_URL` to connect to an existing server instead. If that
server requires basic authentication, set `OPENCODE_SERVER_PASSWORD` as well; the
adapter attaches it to its requests. A configured URL makes the provider
available even when the `opencode` binary is not on `PATH`.

OpenCode supports streaming, tool calls, approvals, and resume.

## Generic PTY provider

The `generic` adapter runs an arbitrary terminal-compatible CLI inside a
pseudo-terminal. It is registered only when `FLEET_GENERIC_BIN` is set:

```bash
export FLEET_GENERIC_BIN=my-agent
export FLEET_GENERIC_ARGS="--interactive --color=never"
```

`FLEET_GENERIC_ARGS` is split on whitespace. The provider streams raw terminal
output and supports interrupt, but it has no structured events, no tool cards,
no permission approval, and no resume. Use it when an agent has no machine
interface beyond a terminal.
