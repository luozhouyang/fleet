Fleet is two long-lived processes and a small set of owned data. `fleet-admin`
serves the browser and REST API, authenticates users, and routes requests.
`fleet-daemon` runs on each machine, owns the filesystem and agent processes,
and connects out to the admin. The split keeps code and agent execution on your
machines while giving you one control plane.

The admin binds `127.0.0.1:8787` by default and serves REST under `/api/v1`,
browser events at `/api/v1/events`, the machine gateway at `/ws/machine`, and
the built SPA. The daemon's only listener is its health endpoint on
`127.0.0.1:18080`; it opens the machine connection outbound and keeps it open.

<Aside type="note" title="The daemon never listens for admin traffic">
`fleet-admin` never dials a machine. It sends every RPC down the WebSocket the
daemon already opened. The daemon has no admin-facing listener and no inbound
port to expose, which is what makes it usable behind NAT, a corporate firewall,
or a laptop lid.
</Aside>

## End-to-end flow

1. **Browser through the edge.** Your browser requests the SPA from the admin.
   If you publish the admin, the request can pass through DNS, Cloudflare
   Access, and a `cloudflared` tunnel, or through a Tailscale tailnet. The admin
   still checks the browser's bearer token; the edge is not the authorization
   layer. See [security](/how-it-works/security/) and
   [deployment](/how-it-works/deployment/).
2. **CLI over REST.** The `fleet` CLI calls the same `/api/v1` routes with an
   admin or user bearer token. It is a client of the admin, not a second control
   plane. `GET /api/v1/health` is public; every other REST route requires a
   token.
3. **Daemon outbound WSS.** Each daemon opens one WebSocket to `/ws/machine`
   with its per-machine token, or in pairing mode with a code. The handshake
   pins an Ed25519 key, then the socket stays open. See
   [connection](/how-it-works/connection/) and
   [enrollment](/how-it-works/enrollment/).
4. **Admin RPC over the same socket.** When you request a file, a Git diff, or
   an agent action, the admin finds the live connection in the registry and
   sends a request envelope. The daemon routes the method to its workspace, Git,
   or agent service and returns a correlated response. The admin never reads a
   repository itself.
5. **Daemon events and a cursor.** The daemon sends events on the same socket.
   Durable agent events carry a `cursor`, the sequence of the daemon's outbox
   row. Sequence-only frames are live events; cursor frames are replayable. See
   [events](/how-it-works/events/).
6. **Events acknowledgement.** After the admin applies a durable event, it
   sends `events.ack` with that exact cursor. The daemon advances its contiguous
   cursor and prunes the outbox. Out-of-order acknowledgements are retained
   until the gap is filled, so a missed frame is replayed.
7. **Browser fan-out.** The admin's event pipeline publishes platform events on
   an in-process bus. Each browser event socket is organization-filtered,
   accepts `Authorization` or `?token=` because browsers cannot set a header on
   a WebSocket upgrade, re-authenticates every 15 seconds, pings every 25
   seconds, and receives `platform.lagged` when it falls behind. Event types include `agent.event`,
   `workspace.event`, `git.status.changed`, `machine.status`,
   `connection.state`, and `platform.lagged`. The browser refetches current
   state on reconnect and on lag.
8. **Owned data in two databases.** The admin database at
   `~/.fleet/admin/fleet-admin.db` holds organizations, users, machines,
   machine-to-organization bindings, workspace metadata, session metadata,
   permission requests, audit records, pairing codes, and revocations. The
   daemon database at `~/.fleet/daemon/fleet-daemon.db` holds workspaces, the
   directory index, sessions, the authoritative transcript (turns, messages,
   tool calls), permissions, the event outbox, cursors, and acknowledgements.
   Each database carries `storage_meta.role` set to `admin` or `daemon`; opening
   one with the wrong role fails before any modification. See
   [storage](/how-it-works/storage/).

### Browser read path

<pre class="mermaid">{`
sequenceDiagram
  autonumber
  participant B as Browser SPA
  participant A as fleet-admin
  participant R as Connection registry
  participant D as fleet-daemon
  participant L as Local service

  B->>A: GET /api/v1/workspaces/workspace_id/files<br/>Authorization: Bearer
  A->>A: authenticate and check org ACL
  A->>R: look up live connection for the machine
  alt machine offline
    R-->>A: no live socket
    A-->>B: 503 machine_offline
  else machine online
    R-->>A: connection handle
    A->>D: request workspace.file.read<br/>message_id
    D->>L: read inside the workspace root
    L-->>D: content or path_denied
    D-->>A: response or error<br/>same message_id
    A-->>B: JSON response
  end
`}</pre>

A browser read is a proxy call, not a cached mirror. The admin authorizes the
workspace id, checks that the owning machine is live, and forwards the RPC. If
the daemon answers with `path_denied`, the admin relays the error rather than
retrying with a different path.

### Agent event path

<pre class="mermaid">{`
sequenceDiagram
  autonumber
  participant RT as Agent runtime
  participant DS as Daemon storage
  participant D as fleet-daemon
  participant A as fleet-admin
  participant BUS as Event bus
  participant B as Browser SPA

  RT->>DS: commit projection and outbox row<br/>one transaction
  RT->>D: processed event with outbox cursor
  D->>A: event agent.event<br/>sequence + cursor
  A->>A: verify session ownership and dedup event_id
  A->>A: apply metadata projection
  A->>BUS: publish platform event
  BUS-->>B: agent.event over /api/v1/events
  A->>D: request events.ack cursor
  D->>DS: advance contiguous cursor and prune
  Note over D,A: Ephemeral deltas have no cursor.<br/>They are live-only and not replayed.
`}</pre>

The admin persists session metadata and permission state, not transcript rows.
The daemon owns the transcript. A browser that needs history asks the admin,
which proxies the daemon; if the machine is offline, session history is marked
unavailable rather than served from an incomplete admin copy.

### RPC surface

Every method uses the same envelope. The catalog is grouped by owner:

| Family | Methods |
| --- | --- |
| Connection | `connection.hello`, `connection.auth_challenge`, `connection.auth`, `connection.accepted`, `connection.heartbeat`, `connection.heartbeat_ack`, `connection.disconnect` |
| Events | `events.ack` |
| Health | `health.get` |
| Agents | `agent.providers.list`, `agent.sessions.create`, `agent.sessions.list`, `agent.sessions.get`, `agent.sessions.send_message`, `agent.sessions.interrupt`, `agent.sessions.resume`, `agent.sessions.shutdown`, `agent.sessions.delete`, `agent.permissions.list`, `agent.permissions.respond` |
| Workspace | `workspace.list`, `workspace.register`, `workspace.get`, `workspace.remove`, `workspace.tree.list`, `workspace.file.read`, `workspace.file.search` |
| Git | `git.status`, `git.diff`, `git.diff.summary`, `git.branches`, `git.log`, `git.stage`, `git.unstage`, `git.commit`, `git.checkout` |

## Design decisions

| Decision | Alternatives | Why | Cost |
| --- | --- | --- | --- |
| Daemon opens an outbound WebSocket to the admin | Inbound listener on each machine; direct Tailscale; admin-side tunnel only | Works behind NAT and firewalls, needs no inbound port, and gives one bidirectional channel for requests and events | The admin must be reachable from each machine; long-lived WebSockets need proxy support |
| One JSON envelope for every frame | Separate REST callbacks, gRPC streams, or one socket per feature | One parser, one correlation model, typed errors, and the same socket in both directions | No binary framing, per-frame JSON overhead, and stream multiplexing is not used |
| Admin proxies RPC instead of storing code | Cloud workspace copy or admin-side checkout | Repository contents, Git state, and agent processes stay on the machine you own | Reads fail while the machine is offline; the admin adds a network hop |
| Two SQLite databases with role markers | One shared database; PostgreSQL | The admin never owns transcript data; each process opens only its role; local-first deployment stays simple | No cross-database joins; history reads require the daemon |
| Live socket registry plus durable metadata | Trust the `machines.status` row for liveness | The registry knows whether a socket exists now; the database alone can be stale | Single-admin-instance design; the registry resets on restart |
| In-process event bus with lag reporting | Per-client outbound queues | A slow browser cannot block the pipeline or other browsers | Lagging clients must refetch state |
| Organization filtering at the admin | Filter only in the SPA | A user never receives another organization's machine events | A per-event organization lookup or cache |
| Browser event socket re-authenticates | Authenticate once at upgrade | Deleted users and rotated tokens stop receiving events | A periodic credential lookup per socket |

## Failure modes and guarantees

| Failure | Behavior | Guarantee |
| --- | --- | --- |
| Admin is unreachable from a daemon | The daemon retries with backoff; no machine work is reachable until the socket returns | Metadata and local agent sessions remain on the machine; requests fail fast instead of hanging |
| Machine is offline | Proxied requests return `machine_offline` (HTTP 503) | The admin never queues RPCs for a later connection |
| Socket drops mid-request | In-flight requests fail; the daemon reconnects and replaces the connection | Pending requests are not replayed as writes; the caller decides whether to retry |
| Late snapshot from a replaced socket | Dropped if a newer connection is live | A reconnect cannot overwrite live metadata with stale providers or workspaces |
| Durable event is lost in transit | Replayed from the daemon outbox until acknowledged | At-least-once delivery; the admin deduplicates by `event_id` |
| Ephemeral delta is lost | Not replayed | The final message or tool event restores authoritative state |
| Browser event subscriber lags | Receives `platform.lagged` with `skipped` and a message | The browser refetches instead of rendering a silent gap |
| Database opened with the wrong role | Startup fails before writing | Pointing the admin at the daemon database cannot delete transcript data |
| Cross-organization resource lookup | Returns `404` rather than `403` | A caller cannot probe ids outside its organization |
| Admin process restarts | Live sockets drop; daemons reconnect; metadata is reloaded from SQLite | Durable machine identity, workspaces, and audit records survive |

## Configuration and limits

| Setting or bound | Default | Notes |
| --- | --- | --- |
| Admin bind | `127.0.0.1:8787` | `[server]`; override with `FLEET_BIND` |
| Daemon health bind | `127.0.0.1:18080` | `[daemon]`; serves `/health` and `/api/v1/health` |
| Public REST health | `GET /api/v1/health` | The only unauthenticated REST route |
| Handshake read timeout | 10 s | Applies to both sides |
| Challenge expiry | 60 s | Informational; the 10 s read timeout is the enforced deadline |
| Proxied RPC timeout | 30,000 ms | `[machines] request_timeout_ms` |
| Snapshot refresh timeout | Clamped to 500–5,000 ms | Uses the same configured request timeout |
| Heartbeat interval | 15 s | Daemon sends `connection.heartbeat` |
| Heartbeat timeout | 45 s | Admin closes a socket with no inbound traffic |
| Reconnect backoff | 500 ms initial, 30 s cap | Exponential with jitter; resets after 30 s connected |
| Per-connection outbound queue | 256 envelopes | A full queue yields `timeout`, not an unbounded buffer |
| Gateway event broadcast | 1,024 | Machine events feeding the admin pipeline |
| Admin platform event bus | 4,096 | Browser fan-out buffer; lag is reported |
| Browser event auth and ping | 15 s / 25 s | Re-authentication and WebSocket ping |
| Pairing code lifetime and attempts | 600 s / 5 | `[auth] pair_code_ttl_secs`, `pair_code_max_attempts` |
| Unauthenticated upgrade limiter | 30 per 600 s per source IP | In-memory; resets on restart; authenticated reconnects are not charged |

<Aside type="caution" title="Cloudflare Access covers the whole hostname">
Access is applied to the hostname, not just the SPA path. A daemon that connects
to that hostname goes through the same Access application, but `fleet-daemon`
does not send Cloudflare Access service-token headers. Remote daemons therefore
need a path that does not require Access — loopback, LAN, or a Tailscale
address — or an explicit bypass policy for `/ws/machine`. `fleet network
connect` writes tunnel and daemon configuration and prints the privileged
commands; it does not create that bypass for you.
</Aside>
